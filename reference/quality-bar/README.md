# Quality bar (reference only, never shipped)

Everything here is for studying what a "good" Emlet email looks like. Nothing in this folder is used at runtime and nothing is deployed (the app lives in `web/`; only `web/public/` is served).

| Put this | Here | Format |
|---|---|---|
| Your good HTML email templates (one file each) | `templates/` | `.html`. Name: `<email-type>__<industry-or-brand>__<style>.html`, e.g. `welcome__record-store__retro.html` |
| A rendered screenshot of each template (desktop ~700px wide, plus mobile if you have it) | `screenshots/` | `.png` / `.jpg`, same base name as the HTML, e.g. `welcome__record-store__retro.png` |
| Photos / illustrations / art that show the image style you want | `images/<mood>/` | e.g. `images/retro-vinyl/`, `images/minimal-product/`, `images/bauhaus-art/` |
| Emails (Emlet outputs or others) you think are BAD, with a reason in `NOTES.md` | `anti-examples/` | `.html` or `.png` |
| Real-brand emails or images you don't have the rights to redistribute | `private/` | anything; git ignores this folder |
| What you like about each one, plus colour and image rules | `NOTES.md` | fill in the template |
| The list of email types | `../email-types.md` | fill in the template |

Rules of thumb:

- Anything that will actually appear in the product (template thumbnails, pinned template photos) must be free to use: Pexels / Unsplash / your own / AI-generated by you. Record the source in `NOTES.md`.
- If you don't want to copy files, paste the HTML (or drop the screenshot) into the chat and I will save it in the right folder.
- Quantity: 8-15 gold-standard templates and 3-5 anti-examples is plenty. More is not better than clearer notes.

The older `../email-samples/` folder stays as is (5 HTML + React samples from earlier work).
